# Long Ascent

An idle game for short check-ins. A few families hold a ford and a timber keep; five ages later their descendants
leave for another world. The settlement is a town that grows: it gains people and rank, its people are given tasks,
research teaches landmarks that are built once and stand in the picture, news arrives with a choice to make, and
heroes bring back places and items that are put to use. Each age has a great work and a trial, and a legacy carries
over to the next world. The picture at the top is the settlement itself: tap it to walk the city, watch the work
going on, and act from there.

- Web app: https://jpvanacor.github.io/long-ascent/
- Android app: https://github.com/jpvanacor/long-ascent/releases/latest/download/long-ascent.apk

The game keeps its progress on the device. Menu, Save gives a text copy of the save that can be loaded on another
device (the web app and the Android app keep separate saves).

## How it is put together

There is no build step: GitHub Pages serves the files as they are.

| Path | What it is |
| --- | --- |
| `index.html`, `css/style.css` | The page and its five age skins |
| `js/core.js` | Rules and data, no DOM. Runs in the browser and in Node |
| `js/scene.js` | The illustrated settlement, drawn on a canvas, and the camera of the city view |
| `js/town.js` | What the player has built, drawn into the settlement: a unit for each purchase, the named buildings, the landmarks, walls and gates |
| `js/city.js` | Life in the settlement: people, carts, work, what the game says is going on, and the places that can be tapped |
| `js/ui.js`, `js/fx.js`, `js/audio.js` | Interface, animations, sound |
| `js/icons.js` | The icons, generated by `tools/icons.js` |
| `audio/` | Music and sound effects, generated by `tools/music/build.js` |
| `sw.js`, `manifest.webmanifest`, `icons/` | Install and offline support for the web app |
| `android/`, `capacitor.config.json`, `scripts/` | The Android wrapper (Capacitor) |
| `tools/` | Pacing simulator, screenshot and play-through tests, asset generators |

## How the game fits together

All of this is data and rules in `js/core.js`; the prices are in its `TUNE` block, written by `tools/freeze.js`.

- **Town.** People come with buildings, landmarks, places found and stages of the great work. People set the rank
  (Hamlet to World city, ten ranks). A rank opens things: tasks for the people at rank 2, places of honour for items
  from rank 3, and some landmarks need a rank.
- **People.** From rank 2 the people are divided in tenths among coin, materials, knowledge and the great work.
  A stage of the great work needs coin, materials and work; a standing crew gives a little work on its own.
- **Buildings.** Every purchase is drawn (up to a limit for each kind). At 10, 25, 50 and 100 a named building is
  raised and doubles the output; the later ones need research first.
- **Research.** Four topics in every age teach a landmark, which is then built once for coin and materials. The
  Research tab shows the next age's topics as shadows.
- **News.** After the Market square is built, something happens now and then and waits for a choice of two.
- **Heroes.** The first victory on each expedition finds a place: a route that pays at once, or a site that needs
  an outpost. Items are placed by the player, on a hero or in the town, with a different effect in each.
- **Goals and chronicle.** Three goals are shown at a time and each pays a reward. The chronicle lists everything
  found and built, with empty pages for what is still to come.
- **Saves.** `SAVE_VERSION` is 3. A save from before version 6 starts a new realm.

## How versions work

`APP_VERSION` in `index.html` is the version. GitHub Pages publishes the web app about a minute after each push. The
Android workflow builds a new APK from the same files and attaches it to a release named after `APP_VERSION`; the
Android app then shows a bar saying a new version is ready. Raise `CACHE` in `sw.js` together with `APP_VERSION`.

A published APK is never replaced by another build: if a release for the current `APP_VERSION` already has one,
the workflow leaves it alone and says so. To publish a change, raise `APP_VERSION`.

The Android signing key (`android/app/long-ascent-release.p12`) is kept in the repository so each build can update
the previous install. Only install APKs from this repository's releases.

## Working on it

```
npm install
npm run serve            # the game at http://127.0.0.1:8123/
npm test                 # the scripted players: how long each kind of player takes to finish
node tools/sim.js cal    # refit the prices to the target pace, then: node tools/freeze.js
node tools/shot.js       # phone-sized screenshots of every screen (needs Playwright and Chrome)
node tools/city.js       # pictures of the city view in every age, by day and by night
node tools/citytest.js   # drags, pinches and taps in the city view, and checks what they do
node tools/bot.js        # a robot plays a whole world through the real buttons
```

After every Android build, the `Device test` workflow installs the released APK on Android 11 to 16
emulators, opens the game, touches a few buttons, reaches the first goal, opens the Town tab and the city view,
and tries Back and Home (`tools/device-test.sh`).

The music is written as note lists and can be rendered again with `node tools/music/build.js`; see `CREDITS.md` for
where the instrument samples come from.
